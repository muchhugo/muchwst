# Security handling

This toolkit supports authorized defensive analysis. Do not report an actual application's vulnerability by opening a public issue here or by attaching secrets, tokens, private evidence or customer data. Use the affected owner's established private disclosure channel. No private inbox or reporting feature is invented by this repository.

For a suspected issue in the toolkit itself, prepare a minimal synthetic reproduction without live target data and contact the repository owner through a confirmed private channel. If no channel is available, request one without publishing sensitive details. The package does not provide incident monitoring, response SLAs, penetration-test certification or a warranty that an agent will find every issue.

Read [scope and safety](shared/safety.md) and [evidence/reporting](shared/evidence-and-reporting.md). Reviewing code does not authorize active remote tests; fixing source does not authorize a production deployment. Keep report artifacts private by default.
